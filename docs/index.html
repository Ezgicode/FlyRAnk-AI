Content Opportunity Prioritization

A public-safe decision-support system for ranking content pages for human review.

0. Abstract

This project asks which content pages should be prioritised for human review when editorial capacity is limited. The analysis uses a March 2026 warehouse slice containing 77,540 pseudonymized content pages and search-performance signals measured during the first 15 days of the month. A transparent rule-based baseline, Logistic Regression, and Random Forest were compared on the same grouped client holdout using a later-window decline proxy. Logistic Regression achieved the strongest observed Precision@50 at 0.28, compared with 0.14 for the baseline, while the baseline and Random Forest were stronger at Precision@20 with 0.20. The output is a public-safe decision-support queue for human review; it does not guarantee that a page will decline or recover after an edit.

1. Problem framing

The system supports a content-review prioritisation decision: which pages should a content editor or SEO analyst inspect first? One row represents one pseudonymized content page. The output is a ranked score, action label, and reason code that supports a human decision to refresh, review a title or snippet, investigate, defer, or take no action.

A false positive can waste editorial time. A false negative can leave an important page outside the review queue. The system applies consistent criteria across a large inventory, but does not replace editorial judgement.

2. Data safety

The analysis uses the FlyRank ML Internship warehouse release and the fact_content_daily_performance table for March 2026. The feature window is 1–15 March and the later outcome window is 16–31 March.

The final features are prior impressions, clicks, average position, CTR, and active days. IDs are used only for grouping and validation. Future outcomes, label-derived fields, existing flags, and previous decision scores are excluded.

The target is a historical later-window decline proxy: a page needs at least 100 prior impressions and at least 20 percent fewer impressions in the later March window. The transparent baseline uses prior impressions, average position, and CTR. Logistic Regression is retained as the main readable model.

5. Limitations

This work measures associations within one historical March 2026 slice. It does not prove that content changes cause performance recovery. The proxy is based on later impressions, not conversion value, revenue, page quality, or user satisfaction.

The models do not observe page text, search intent, SERP features, competitors, technical conditions, seasonal demand, or business priorities. The grouped client holdout is more honest than a random split, but it remains one historical evaluation.

Decision boundary Scores prioritise human review. They must not automatically publish, rewrite, delete, merge, canonicalise, or change internal links.

6. Ranked recommendations

The historical top-20 queue contains 10 refresh briefs, 9 title/snippet reviews, and 1 general human refresh review.

1

Human refresh review

Investigate the page context when the suitable intervention is not yet clear from the observable signals.

No-go automation list: publishing, rewriting, deleting, merging, canonicalising, or treating a score as proof of future decline must remain human decisions.

7. Reproducibility

The full notebook workflow is available in the public project repository. The analysis uses DuckDB, pandas, NumPy, scikit-learn, Matplotlib, and a Hugging Face read token stored outside the repository.

The grouped split uses random_state=42. The complete reproducibility record is available in capstone_report.md, and the executable implementation is in capstone.ipynb.
