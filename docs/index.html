Content Opportunity Prioritization

A public-safe decision-support system for ranking content pages for human review.

Abstract Data Method Results Recommendations Reproducibility

0. Abstract

This project asks which content pages should be prioritised for human review when editorial capacity is limited. The analysis uses a March 2026 warehouse slice containing 77,540 pseudonymized content pages and search-performance signals measured during the first 15 days of the month. A transparent rule-based baseline, Logistic Regression, and Random Forest were compared on the same grouped client holdout using a later-window decline proxy. Logistic Regression achieved the strongest observed Precision@50 at 0.28, compared with 0.14 for the baseline, while the baseline and Random Forest were stronger at Precision@20 with 0.20. The output is a public-safe decision-support queue for human review; it does not guarantee that a page will decline or recover after an edit.

1. Problem framing

The system supports a content-review prioritisation decision: which pages should a content editor or SEO analyst inspect first? One row represents one pseudonymized content page. The output is a ranked score, action label, and reason code that supports a human decision to refresh, review a title or snippet, investigate, defer, or take no action.

A false positive can waste editorial time. A false negative can leave an important page outside the review queue. Data and machine learning help apply consistent criteria across a large inventory, but do not replace editorial judgement.

2. Data safety

The analysis uses the FlyRank ML Internship warehouse release and the fact_content_daily_performance table for March 2026. The feature window is 1–15 March; the later outcome window is 16–31 March.

The final features are prior impressions, clicks, average position, CTR, and active days. Client and content IDs are used only for grouping and validation. Future-window impressions, the decline label, future-derived ratios, existing flags, and prior scores are excluded.

3. Baseline and methodology

The target is a historical later-window decline proxy: pages need at least 100 impressions in the first 15 days and at least 20 percent fewer impressions in the later March window. The transparent baseline uses only prior impressions, average position, and CTR, with additional review priority for visible pages in positions 21–50.

Logistic Regression is the main readable model. Random Forest is a non-linear comparison. Evaluation uses GroupShuffleSplit by pseudonymized client with random_state=42. The page-level frame is sorted by client and content ID before splitting so the evaluation is reproducible.

5. Limitations

This work measures associations within one historical March 2026 slice. It does not prove that content changes cause performance recovery. The proxy is based on later impressions, not conversion value, revenue, page quality, or user satisfaction.

The models cannot observe page text, search intent, SERP features, competitors, technical conditions, seasonal demand, or business priorities. The grouped client holdout is more honest than a random page-level split, but it remains one historical evaluation.

The queue is decision support only. It must not automatically publish, rewrite, delete, merge, canonicalise, or change internal links.

A refresh brief prompts review of freshness, topic coverage, structure, internal links, and intent. A title/snippet review examines title, metadata, and search-result presentation before a full rewrite is considered. Every recommendation requires a reviewer to inspect search intent, SERP context, quality, effort, business value, seasonality, and technical conditions.

7. Reproducibility

The notebook workflow is available in the public project repository. The core analysis is reproduced by running the numbered notebooks followed by capstone.ipynb.

The analysis uses Python with DuckDB, pandas, NumPy, scikit-learn, Matplotlib, and an approved Hugging Face read token stored outside the repository. The capstone notebook creates a public-safe metrics receipt and reusable figures; row-level queues are regenerated and not committed publicly.

Read the complete methodology and reproducibility record in capstone_report.md.
